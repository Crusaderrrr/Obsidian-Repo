## Базовые вещи

- **`sudo`** — «выполнить от имени администратора (root)». Как ключ от служебного помещения: обычному пользователю многие системные файлы трогать нельзя. При первом `sudo` система спросит ваш пароль (в Linux Mint при вводе показываются звёздочки).
- **`apt`** — менеджер пакетов, «магазин приложений» в командной строке.
- **`nano`** — простой текстовый редактор в терминале:
  - стрелки — перемещение;
  - **Ctrl+O**, затем **Enter** — сохранить;
  - **Ctrl+X** — выйти;
  - **Ctrl+W** — поиск по файлу.
- **Вставка в терминал** — **Ctrl+Shift+V** (не просто Ctrl+V).
- **`systemctl`** — управление службами (программами, которые работают в фоне). Диспетчер, который их запускает и останавливает.
- **`#` в начале строки** конфига — строка закомментирована (отключена). Чтобы настройка заработала, `#` надо удалить.
- **`|` (pipe)** — передать вывод одной команды на вход другой.
- **`grep`** — оставить только строки, содержащие нужное слово.

## Шаг 0. Подготовка системы

**Зачем:** обновить систему и поставить нужные утилиты.

```bash
sudo apt update
```
Скачивает свежий **список** доступных программ и обновлений, ничего не устанавливая. Как обновить меню в ресторане, ещё ничего не заказав.

```bash
sudo apt full-upgrade -y
```
Устанавливает все доступные обновления. `-y` — автоматически отвечать «да». Может занять 5–20 минут.

```bash
sudo apt install -y openssh-server smartmontools lm-sensors htop
```

| Программа | Зачем |
|---|---|
| `openssh-server` | подключение к ноутбуку с другого компьютера |
| `smartmontools` | проверка здоровья SSD (команда `smartctl`) |
| `lm-sensors` | температуры и обороты вентиляторов (команда `sensors`) |
| `htop` | наглядный диспетчер задач |

**Ожидаемо:** нет красных строк `E:` (ошибок). Предупреждения `W:` обычно не страшны.

## Шаг 1. Удалённый доступ по SSH

**Зачем:** управлять ноутбуком с основного компьютера. SSH — удалённый пульт: вы печатаете команды у себя, выполняются они на ноутбуке.

### 1.1. Включить SSH-сервер

```bash
sudo systemctl enable --now ssh
```
- `enable` — запускать службу **автоматически при каждой загрузке**;
- `--now` — и **запустить прямо сейчас**.

Проверка:
```bash
systemctl status ssh
```
Должно быть **`active (running)`**. Выйти — клавиша **q**.

### 1.2. Узнать имя пользователя и IP-адрес

```bash
whoami
```
Выводит имя пользователя (например, `nikita`). Запомните его.

```bash
ip a
```
Показывает сетевые интерфейсы. Ищите блок `enp...` или `eth...` (Ethernet; `wlp...` — это Wi‑Fi). В нём:
```
inet 192.168.1.45/24 ...
```
Ваш адрес — **`192.168.1.45`** (без `/24`).

Там же запишите **MAC-адрес**: строка `link/ether aa:bb:cc:dd:ee:ff`.

### 1.3. Закрепить IP в роутере

**Зачем:** роутер выдаёт адреса «на время». Без закрепления IP однажды сменится, и вы «потеряете» сервер. Как место на парковке: без брони каждый раз новое.

1. Откройте в браузере адрес роутера (обычно `192.168.1.1` или `192.168.0.1`, часто написан на наклейке снизу).
2. Найдите раздел **DHCP / LAN / Address Reservation / Static Lease / Привязка адресов**.
3. Добавьте запись: MAC-адрес ноутбука + его текущий IP.
4. Сохраните.

### 1.4. Подключиться с основного компьютера

> Эти команды выполняются **на основном компьютере**, не на ноутбуке.

Создать SSH-ключ, если его ещё нет (электронный пропуск вместо пароля):
```bash
ssh-keygen -t ed25519
```
- `-t ed25519` — современный надёжный тип ключа.
- На вопросы — **Enter**. Если ключ уже существует, ответьте `n`, чтобы не перезаписать.

Скопировать ключ на ноутбук:
```bash
ssh-copy-id nikita@192.168.1.45
```
Один раз спросит пароль от ноутбука. На вопрос `Are you sure you want to continue connecting?` ответьте `yes`.

> На Windows `ssh-copy-id` нет — нужен аналог через PowerShell.

Подключиться:
```bash
ssh nikita@192.168.1.45
```
**Ожидаемо:** приглашение сменится на `nikita@имя-ноутбука:~$`, пароль не спрашивается. Выйти — `exit`.

**Дальше все шаги можно делать по SSH.**

## Шаг 1.5. (Опционально) sudo без пароля

### Компромисс

Пароль `sudo` — последняя дверь между «зашёл под вашим пользователем» и «полный контроль над системой». Без пароля любой, кто получит доступ к аккаунту (украденный ключ, дыра в сервисе), сразу становится root. Как ключ, оставленный в замке сейфа: удобно, пока в квартиру никто не попал.

Для домашнего сервера, доступного только из локальной сети и только по SSH-ключу, это приемлемый риск.

### Настройка

```bash
sudo visudo -f /etc/sudoers.d/nikita
```
- `visudo` — специальный редактор для настроек `sudo`, который **проверяет синтаксис перед сохранением**. Никогда не редактируйте эти файлы обычным `nano`: опечатка сломает `sudo` целиком, и вы останетесь без админских прав.
- `-f /etc/sudoers.d/nikita` — отдельный файл с правилами, главный `/etc/sudoers` не трогаем.
- **В имени файла не должно быть точки и `~`** (например, `nikita.conf` не подойдёт), иначе `sudo` молча его проигнорирует.

Замените `nikita` на своё имя и впишите **одну** строку:

| Вариант | Строка | Что делает |
|---|---|---|
| 1. Компромисс | `Defaults:nikita timestamp_timeout=60` | пароль раз в 60 минут (по умолчанию 15) |
| 2. Точечно | `nikita ALL=(ALL) NOPASSWD: /usr/local/bin/server-power.sh` | без пароля только для этого скрипта |
| 3. Полностью | `nikita ALL=(ALL) NOPASSWD: ALL` | без пароля всегда |

Как читать строку: `пользователь ГДЕ=(ОТ_ИМЕНИ_КОГО) NOPASSWD: КАКИЕ_КОМАНДЫ`.
- `nikita` — для кого правило;
- первое `ALL` — на любом компьютере (для вас всегда `ALL`);
- `(ALL)` — от имени любого пользователя, включая root;
- `NOPASSWD:` — не спрашивать пароль;
- последнее `ALL` или путь — к каким командам относится.

Если `visudo` пишет `syntax error` и спрашивает `What now?` — нажмите **e** и исправьте. **Не сохраняйте файл с ошибкой.**

### Проверка

В **новой** SSH-сессии:
```bash
sudo -k
sudo whoami
```
- `sudo -k` — «забыть» запомненный пароль, чтобы проверка была честной;
- `sudo whoami` должен вывести `root` без запроса пароля (для варианта 3).

Откат:
```bash
sudo rm /etc/sudoers.d/nikita
```

### Если выбрали вариант 3 — отключите вход по SSH паролем

> ⚠️ Сначала убедитесь, что вход по ключу работает (шаг 1.4). Текущую SSH-сессию не закрывайте, пока не проверите подключение в новом окне.

```bash
sudo nano /etc/ssh/sshd_config.d/no-password.conf
```
Впишите:
```
PasswordAuthentication no
```
«Не принимать пароли при входе по SSH, только ключи».

```bash
sudo systemctl restart ssh
```

> Если когда-нибудь откроете сервер в интернет (проброс портов), лучше вернуться к варианту 1.

## Шаг 2. Ноутбук не должен засыпать

**Зачем:** по умолчанию ноутбук засыпает при закрытии крышки или в простое. Для сервера это значит «пропал из сети».

### 2.1. Системная настройка (logind)

`logind` — служба, которая решает, что делать при закрытии крышки, нажатии кнопки питания и т. д.

```bash
sudo nano /etc/systemd/logind.conf
```
**Ctrl+W** → `HandleLidSwitch` → Enter. Найдите строки:
```
#HandleLidSwitch=suspend
#HandleLidSwitchExternalPower=suspend
#HandleLidSwitchDocked=ignore
```
Приведите к виду (убрать `#`, заменить значения):
```
HandleLidSwitch=ignore
HandleLidSwitchExternalPower=ignore
HandleLidSwitchDocked=ignore
```
- `HandleLidSwitch` — закрытие крышки (общий случай);
- `HandleLidSwitchExternalPower` — то же при подключённой зарядке;
- `HandleLidSwitchDocked` — при подключённом мониторе или доке;
- `ignore` — ничего не делать.

Сохранить, выйти, применить:
```bash
sudo systemctl restart systemd-logind
```
Перезапускает службу, чтобы она перечитала конфиг.

> Если вы сидите за ноутбуком в графике, эта команда может выкинуть на экран входа — это нормально. На SSH не влияет.

### 2.2. Настройка в графике Mint

**Зачем:** у Cinnamon свой менеджер питания, и пока вы залогинены в графике, он может перекрывать logind. Два «начальника» должны говорить одно и то же.

**Меню → Параметры системы → Управление питанием:**
- «При закрытии крышки» → **Ничего не делать** (и от батареи, и от сети);
- «Переводить в режим сна» → **Никогда**;
- «Отключать экран» — можно оставить (например, 5 минут), это экономит энергию.

### 2.3. Проверка

Закройте крышку, подождите 1–2 минуты, подключитесь по SSH с основного компьютера. Подключились — всё работает.

## Шаг 3. Батарея до 60% и тихий режим

### Как это устроено

В Linux многие настройки железа представлены как **файлы** в папке `/sys`. Это не настоящие файлы на диске, а «окошки» в драйверы: прочитать файл — узнать текущее значение, записать — отдать команду. Как термостат: посмотреть — узнать температуру, повернуть ручку — изменить.

Эти значения **живут только до перезагрузки**, поэтому пишем скрипт и ставим его на автозапуск.

### 3.1. Проверить поддержку

```bash
ls /sys/class/power_supply/
```
`ls` — показать содержимое папки. Ожидается что-то вроде `ACAD BAT0`. **`BAT0`/`BAT1` — батарея**, `AC...` — зарядка.

```bash
cat /sys/class/power_supply/BAT*/charge_control_end_threshold
```
`cat` — вывести содержимое файла. `*` подставляет любой номер батареи. Файл означает «до скольки процентов заряжать».
- **Число** (обычно `100`) — поддерживается.
- `No such file or directory` — драйвер не умеет на этой модели (нужен другой путь, например `asusctl`).

```bash
cat /sys/firmware/acpi/platform_profile_choices
```
Доступные профили. Ожидается:
```
quiet balanced performance
```
Аналог режимов Armoury Crate из Windows:
- `quiet` — ограниченная мощность, вентиляторы на минимуме;
- `balanced` — обычный режим;
- `performance` — максимум мощности и шума.

```bash
cat /sys/firmware/acpi/platform_profile
```
Текущий профиль.

### 3.2. Создать скрипт

```bash
sudo nano /usr/local/bin/server-power.sh
```
`/usr/local/bin/` — стандартная папка для своих системных скриптов.

Содержимое:
```bash
#!/bin/bash
# Ограничение заряда батареи
for f in /sys/class/power_supply/BAT*/charge_control_end_threshold; do
  [ -w "$f" ] && echo 60 > "$f"
done
# Тихий профиль вентиляторов/мощности
if [ -w /sys/firmware/acpi/platform_profile ]; then
  echo quiet > /sys/firmware/acpi/platform_profile
fi
```
Построчно:
- `#!/bin/bash` — «выполнять программой bash», обязательная первая строка скрипта;
- `#` дальше — комментарии для человека;
- `for f in ...; do ... done` — для каждой найденной батареи выполнить то, что внутри;
- `[ -w "$f" ]` — проверка «файл существует и в него можно писать»;
- `&&` — выполнить следующую команду, только если предыдущая успешна (поэтому скрипт не упадёт, если файла нет);
- `echo 60 > "$f"` — `echo` выводит `60`, а `>` направляет вывод в файл: «записать 60 в порог заряда»;
- `if [ -w ... ]; then ... fi` — то же для профиля: если файл есть, записать `quiet`.

Сделать исполняемым:
```bash
sudo chmod +x /usr/local/bin/server-power.sh
```
`chmod +x` — дать право на выполнение. Без этого Linux считает файл просто текстом.

Проверить вручную:
```bash
sudo /usr/local/bin/server-power.sh
cat /sys/class/power_supply/BAT*/charge_control_end_threshold
cat /sys/firmware/acpi/platform_profile
```
Ожидаемо: **`60`** и **`quiet`**.

### 3.3. Автозапуск при загрузке (systemd-сервис)

```bash
sudo nano /etc/systemd/system/server-power.service
```
Содержимое:
```ini
[Unit]
Description=Battery limit and quiet profile

[Service]
Type=oneshot
ExecStart=/usr/local/bin/server-power.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```
- `Description` — название сервиса (видно в статусе);
- `Type=oneshot` — выполнить **один раз** и завершиться (в отличие от SSH, который работает постоянно);
- `ExecStart` — что запустить;
- `RemainAfterExit=yes` — после завершения считать сервис «активным», чтобы статус не путал;
- `WantedBy=multi-user.target` — запускать при обычной загрузке (этап, когда система готова к работе).

```bash
sudo systemctl daemon-reload
```
«Перечитай список сервисов, я добавил новый».

```bash
sudo systemctl enable --now server-power.service
```
Запускать при загрузке + запустить сейчас.

Проверка:
```bash
systemctl status server-power.service
```
Ожидаемо: **`active (exited)`** — это правильно для `oneshot`. Выйти — **q**.

### 3.4. Важные моменты

**Лимит не разряжает батарею, он только останавливает зарядку.** Если батарея сейчас на 100%, она так и останется. Один раз отключите зарядку, дайте сесть до ~55–60% и снова подключите. Текущий заряд:
```bash
cat /sys/class/power_supply/BAT*/capacity
```

**`quiet` можно держать постоянно.** При нулевой нагрузке он ограничивает только пиковую мощность, которой вы не пользуетесь. Временно переключить на более мощный режим:
```bash
echo balanced | sudo tee /sys/firmware/acpi/platform_profile
```
> Почему `tee`, а не `sudo echo ... > файл`: в варианте с `>` `sudo` применяется только к `echo`, а запись в файл выполняется от обычного пользователя, поэтому будет «Permission denied». `tee` сам пишет в файл и запускается через `sudo`. Внутри скрипта этой проблемы нет: он целиком запускается от root.

## Шаг 4. Усыпить дискретную видеокарту

**Зачем:** в ноутбуке две видеокарты — встроенная в процессор (экономная) и RTX 3050 Ti (прожорливая). NVIDIA, работающая впустую, — это лишние 5–15 Вт и тепло. Как держать машину заведённой на парковке.

```bash
prime-select query
```
Текущий режим:
- `nvidia` — всегда работает NVIDIA (худшее для сервера);
- `on-demand` — работает встроенная, NVIDIA просыпается по необходимости;
- `intel` — NVIDIA выключена полностью.

> `command not found` → стоит открытый драйвер nouveau. **Меню → Менеджер драйверов** → рекомендуемый `nvidia-driver-...` → применить → перезагрузить.

Выбрать режим:

```bash
sudo prime-select intel
```
Если видеокарта **не нужна вообще**. Название историческое: на AMD это означает «только встроенная графика Radeon».

```bash
sudo prime-select on-demand
```
Если NVIDIA **может понадобиться** (транскодирование в Jellyfin, локальные нейросети).

```bash
sudo reboot
```
Переключение требует перезагрузки.

### Проверка (для on-demand)

```bash
lspci | grep -i nvidia
```
- `lspci` — список всех PCI-устройств;
- `grep -i nvidia` — только строки с «nvidia» (`-i` — без учёта регистра).

Пример вывода:
```
01:00.0 VGA compatible controller: NVIDIA Corporation GA107M [GeForce RTX 3050 Ti Mobile]
```
`01:00.0` — адрес карты. Подставьте в команду:
```bash
cat /sys/bus/pci/devices/0000:01:00.0/power/runtime_status
```
- `suspended` — спит;
- `active` — работает (подождите минуту после загрузки и проверьте снова).

> ⚠️ **Не используйте `nvidia-smi` для проверки** — он сам будит карту. Как проверять, спит ли человек, тряся его за плечо.

В режиме `intel` проверка не нужна.

## Шаг 5. (Опционально) Отключить графический интерфейс

**Зачем:** рабочий стол Cinnamon занимает около 1 ГБ RAM. Серверу экран не нужен.

> ⚠️ Только когда SSH точно работает (шаг 1). Иначе для управления понадобятся монитор и клавиатура.

```bash
sudo systemctl set-default multi-user.target
sudo reboot
```
«При загрузке останавливаться на текстовом режиме». `multi-user.target` — система работает без графики, `graphical.target` — с графикой.

Вернуть графику:
```bash
sudo systemctl set-default graphical.target
sudo reboot
```

> Без графики настройки из шага 2.2 не действуют, но они и не нужны: работает logind из шага 2.1.

## Шаг 6. (Опционально) Ночной сон по расписанию

Только если в `quiet` ноутбук всё равно мешает шумом. Учтите: спящий сервер ночью недоступен (бэкапы, обновления, доступ к сервисам).

`rtcwake` усыпляет компьютер и заводит «будильник» в аппаратных часах (RTC — чип, который хранит время при выключенном компьютере).

### 6.1. Тест

```bash
sudo rtcwake -m mem -s 120
```
- `-m mem` — сон в оперативной памяти: всё выключено, кроме RAM; вентиляторы стоят, ~1 Вт;
- `-s 120` — проснуться через 120 секунд.

**Ожидаемо:** SSH «зависнет», через 2 минуты ноутбук проснётся. Если сессия отвалилась — подключитесь заново.

После пробуждения проверьте:
- SSH работает;
- `cat /sys/class/power_supply/BAT*/charge_control_end_threshold` всё ещё `60`.

> С драйверами NVIDIA сон в Linux иногда глючит (не поднимается сеть, чёрный экран). Если тест не прошёл — оставайтесь на `quiet` без сна.

### 6.2. Расписание через cron

`cron` — встроенный планировщик: «в такое-то время выполни такую-то команду».

```bash
sudo crontab -e
```
Открывает задачи пользователя root (усыплять систему может только root). При первом запуске выберите редактор `nano`.

Добавьте в конец файла:
```
0 1 * * * /usr/sbin/rtcwake -m mem -t $(date +\%s -d 'today 07:00') && /usr/local/bin/server-power.sh
```
- `0 1 * * *` — пять полей: **минута, час, день месяца, месяц, день недели**; `*` — «любой». Итого «в 01:00 каждый день»;
- `-t ...` — проснуться в конкретный момент;
- `$(date +\%s -d 'today 07:00')` — «сегодня 07:00» в секундах с 1970 года (формат для rtcwake);
- `\%` — в cron символ `%` особенный, его **обязательно экранировать**, иначе строка молча не сработает;
- `&& /usr/local/bin/server-power.sh` — на некоторых ASUS порог батареи **сбрасывается после сна**. `rtcwake` возвращает управление только после пробуждения, поэтому скрипт восстановит настройки сразу после того, как ноутбук проснётся.

Проверить, что задача записалась:
```bash
sudo crontab -l
```

Проверить часовой пояс (cron работает по системному времени):
```bash
timedatectl
```
Должно быть `Atlantic/Canary`. Если нет:
```bash
sudo timedatectl set-timezone Atlantic/Canary
```

## Шаг 7. Финальная проверка

**Зачем:** убедиться, что после перезагрузки всё применилось само.

```bash
sudo reboot
```
Через 1–2 минуты подключитесь по SSH.

```bash
cat /sys/class/power_supply/BAT*/charge_control_end_threshold
```
Ожидаемо: **`60`**.

```bash
cat /sys/firmware/acpi/platform_profile
```
Ожидаемо: **`quiet`**.

```bash
sensors
```
Температуры и вентиляторы:
- `Tctl` / `k10temp` — температура процессора;
- `cpu_fan` / `gpu_fan` — обороты (RPM);
- в простое ориентир **40–55°C**, вентиляторы на низких оборотах или `0 RPM`;
- выше 60°C без нагрузки — вероятно, пыль, чистка желательна.

```bash
sudo smartctl -a /dev/nvme0 | grep -iE "percentage used|media|errors"
```
- `smartctl -a /dev/nvme0` — полный отчёт о здоровье SSD;
- `grep -iE "..."` — только нужные строки (`-E` позволяет несколько слов через `|`).

Что смотреть:
- `Percentage Used` — износ: 0–20% отлично, до 80% нормально, ближе к 100% пора менять;
- `Media and Data Integrity Errors` — должно быть **0**;
- `Error Information Log Entries` — немного записей часто бывает и не критично.

> Если `/dev/nvme0` не найден — посмотрите имя диска командой `lsblk`.

```bash
htop
```
- полоски вверху — загрузка ядер, в простое почти пустые (0–5%);
- `Mem` — использование оперативки;
- **F6** → `PERCENT_CPU` — сортировка по нагрузке; если что-то постоянно грузит CPU, это и есть причина шума;
- выйти — **F10** или **q**.

## Физическое размещение

- **Твёрдая поверхность**, решётки сзади и снизу открыты. Подложите что-нибудь под задний край, чтобы снизу был зазор.
- Не в закрытый шкаф, не на кровать или ткань.
- **Раз в 1–2 месяца** проверяйте батарею: если крышка неплотно закрывается, корпус «выпирает» или тачпад приподнялся — это вздутие. Сразу выключить, батарею вынуть или заменить.
- Чистка от пыли: продуть вентиляторы и радиаторы. **Процессор без опыта не вскрывать**: на многих ROG Strix 2020–2021 вместо термопасты стоит жидкий металл.
