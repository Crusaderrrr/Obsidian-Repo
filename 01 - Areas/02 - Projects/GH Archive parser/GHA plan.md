**1. Каркас.** Spring Boot 4 на Java 25, Docker Compose с Postgres 18, Flyway, один интеграционный тест на Testcontainers, CI на GitHub Actions. CI ставлю сразу, потому что потом его прикручивать лень, а без него регрессии при оптимизации будут незаметны.  
Готово, когда: `docker compose up` поднимает всё, CI зелёный.

**2. Импорт одного часа.** Скачивание файла, потоковое чтение gzip → построчно → Jackson, фильтр нужных событий (`WatchEvent`, `ForkEvent`, `CreateEvent` только с `ref_type = repository`), запись в таблицу событий, партиционированную по времени.  
Готово, когда: повторный импорт того же часа не меняет количество строк, и это покрыто тестом; импорт, прерванный посередине, при перезапуске доводится до конца без дублей.

**3. Регулярный импорт и догрузка истории.** Ежечасный запуск, корректная обработка «файл ещё не опубликован», команда или endpoint для загрузки диапазона дат, политика хранения (удаление старых партиций целиком, а не через `DELETE`).  
Готово, когда: сервис сутки работает сам без пропущенных часов, а история за две недели загружается одной командой.

**4. Тренды.** Почасовые агрегаты по репозиториям, твоя формула аномального роста, endpoint'ы для трендов за 24 часа и 7 дней и для истории репозитория.  
Готово, когда: на двух неделях данных тренды отдаются быстро, а в топе оказываются репозитории, которые ты, посмотрев на них глазами, согласен считать взлетающими. Второй критерий важнее первого: если в топе мусор, формулу надо менять.

**5. Метрики.** Micrometer, Prometheus, Grafana: скорость и длительность импорта, латентность endpoint'ов, пул соединений, JVM.  
Готово, когда: по дашборду видно, что происходит с сервисом, без чтения логов.

**6. Нагрузка и оптимизация.** Увеличь объём данных до месяца или больше, дай нагрузку через Locust, ищи узкие места через `EXPLAIN (ANALYZE, BUFFERS)`, `pg_stat_statements`, JFR и async-profiler.  
Готово, когда: найдены и исправлены минимум три реальных узких места, и каждое записано в журнал с цифрами до и после. Это главный этап всего проекта, на него не жалей времени.

**7. Обогащение метаданными.** Подтягивание языка и описания через GitHub API, очередь задач в Postgres через `SKIP LOCKED`, Resilience4j для ретраев и лимитов, фильтр трендов по языку.  
Готово, когда: при упоре в лимит GitHub API сервис не падает и не теряет задачи, а продолжает с того места, где остановился.

**8. Витрина.** Дашборд на React + TypeScript, Telegram-бот на Python, деплой на недорогой VPS, чтобы в портфолио была живая ссылка, и README с архитектурой и журналом оптимизаций из этапа 6.  
Готово, когда: человек, впервые открывший репозиторий, за пять минут понимает, что делает сервис и какие проблемы ты в нём решал.

**9. Антинакрутка, по желанию.** Только если после этапа 8 ещё есть желание. Проект полноценен и без неё.
