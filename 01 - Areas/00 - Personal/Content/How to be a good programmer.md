
The core insight is that **wrong decisions are cheap early and catastrophically expensive late**.

To be a professional, not average, follow that simple rule of three:
1. **Make it work** -> even if ugly, it should just work
2. **Make it right** -> refactor toward clean structure [[Clean Code]].
3. **Make it fast** -> optimize only after profiling proves there is a bottleneck 

If those steps are followed in order and without skipping any, the code will be good.

The main trait that separates average programmer with professional - is *the ability to manage complexity*.

> [!important]  ALWAYS REFACTOR YOUR CODE
